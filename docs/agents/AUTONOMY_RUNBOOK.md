# Windows autonomy integration — start and resume

Delivery status: PARTIEL. Branch assist/autonomy-integration-20261119, base main 44ca6bd900505b587220244a15e14e789a8b501a. No service, scheduler, deployment or main merge.

## What runs

start-agents.ps1 invokes Runtime, an extension of the existing PR119 Windows Supervisor. It reuses FileStore CAS and Inbox from PR118/119, the PR120 anonymous Kilo free provider, PR121 project memory and PR122 evaluation safeguards. The original Codex transport is imported as a dependency; this launcher never calls Codex or its paid models.

Supported queue contracts are synthetic text artifacts for tel99-analyst, tel99-dev and tel99-verifier. These are specialist identities passed to the real native model gateway, not separate connected Kilo Agent Manager sessions. Nine other historical roles are reserved. General coding work, Hermes and cloud missions are not admitted by this adapter. Existing native CLI separately generates programs and verifies them in Docker.

The executable path is REQUEST / local validation → permanent exclusive claim → ACK NOT_STARTED → RUNNING → real worker process → durable WORKER_EXITED receipt → fixed independent verifier process → project memory → ACCEPTED or REJECTED → next eligible contract. Missing verifier or uncertain crash produces AWAITING_HUMAN. Provider error produces BLOCKED. Terminal results never restart automatically.

## Start once

From the integration worktree in PowerShell:

~~~powershell
.\start-agents.ps1 -Action RUN -Registry .\.tel99-automation-state\acceptance-live-20261119\registry.json -RegistrySha256 42a3bdf1bf997bdbb2490d29739ca53309587c9df23e1bf4e57ab932db6c7c7b -State .\.tel99-automation-state\acceptance-live-20261119\runtime -Seconds 300
~~~

This resumes the two already completed acceptance missions without another model call. The private registry is on this PC and is not committed. A new installation needs an operator-approved registry and its externally pinned SHA256. The seal helper computes content fingerprints; it is not an approval signature. Never trust an approval generated by a model or arbitrary issue text.

Registry format: a JSON object with missions (list) and approvals (map of mission ID to canonical mission fingerprint). Each mission has exactly id, project=synthetic, owner=kilo, priority, dependencies, specialist, synthetic_data=true, objective and expected_sha256. Only an operator may establish the trusted registry hash; the model worker receives no tools and no registry-write access. At most20 unique missions per registry; dependencies must be present in that registry and accepted with the same current fingerprint. Changing the registry requires a new explicit trusted pin.

The runtime polls this durable local source every10seconds, for at most the requested duration (1–3600seconds). One permanent claim per identity prevents repeat provider calls even across launches. No live GitHub writer or generic issue-comment parser is enabled. GitHub contracts and the existing cloud supervisor remain separate until their authenticated transport is accepted.

## STATUS and STOP

~~~powershell
.\start-agents.ps1 -Action STATUS -State .\.tel99-automation-state\acceptance-live-20261119\runtime
.\start-agents.ps1 -Action STOP -State .\.tel99-automation-state\acceptance-live-20261119\runtime
~~~

STOP interrupts monitoring and terminates an active native worker. STOP_REQUESTED is only a signal; STOPPED is the supervisor shutdown observation. The heartbeat can be stale for up to30seconds after a crash and does not independently attest PID liveness. Quota is reported unknown; the launcher never invents remaining free capacity. Each provider call checks current free catalogue/prices and response cost0, with no paid fallback.

A STOP marker persists. To explicitly resume after checking status, archive stop.request under a timestamped name in the same state directory, then launch again. Do not erase claims, receipts or proof files. If RUNNING has no durable worker result, the next start holds it in AWAITING_HUMAN rather than replaying an uncertain effect. A WORKER_EXITED result resumes only verification. An unavailable verifier remains AWAITING_HUMAN until reconciliation.

The session deadline prevents new claims and bounds the active worker; an already started fixed verifier has a15second timeout. End-of-session shutdown leaves checkpoints and memory for the next explicit launch. No work continues after this local executor exits.
